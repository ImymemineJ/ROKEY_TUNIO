## 3. 띄우기

새 터미널마다 `export ROS_DOMAIN_ID=10`. Wi-Fi 에서 서로 안 보이면 정정인 PC 에서
`fastdds discovery -i 0 -l 0.0.0.0 -p 11811` 를 띄우고 양쪽에 `ROS_DISCOVERY_SERVER` 를 잡는다
(정정인 PC `127.0.0.1:11811`, 로봇 PC `<정정인 PC IP>:11811`). `ros2` 명령이 아무것도 못 찾으면 그 터미널에 `export ROS_SUPER_CLIENT=TRUE`.

```bash
# 로봇 제어 PC · 터미널 1 — 두산 브링업
source ~/ws_cobot_pjt/ws_dsr/install/setup.bash
ros2 launch m0609_rg2_bringup bringup.launch.py mode:=real host:=192.168.1.100

# 로봇 제어 PC · 터미널 2 — 우리 노드. 먼저 dry_run
source ~/tunio_ws/install/setup.bash
ros2 launch tunio_robot robot.launch.py dry_run:=true

# 정정인 PC
source ~/tunio_ws/install/setup.bash
ros2 launch tunio_bringup station.launch.py device:=<마이크 번호>
```

- [ ] 웹 `http://localhost:8080` 오른쪽 위 "연결됨"
- [ ] `ros2 service list | grep robot` 에 `/robot/pause` `/robot/resume` 보임
- [ ] `ros2 param get /task_manager adaptive_gain` → `True`

### dry_run 에서 버튼 왕복 (로봇 안 움직임)

- [ ] 페그 재등록 → 완료 문구
- [ ] 시작 → 진행. 발현 단계에서 사람이 그 줄을 손으로 튕기면 마이크까지 확인된다
- [ ] 일시정지 → 멈춤 · 재개 → 이어감 · 취소 → "취소"

**여기까지는 비동기 이동을 안 탄다.** 연결과 버튼만 본 것이다. dry_run 은 취소 뒤 재시작 불필요.

## 4. 실기 — 첫 실물 검증

터미널 2 를 Ctrl+C → `ros2 launch tunio_robot robot.launch.py dry_run:=false`

- [ ] 페그 재등록 → 네 줄 등록 → 대기 자세 복귀
- [ ] 시작 → 첫 줄 발현·측정·조절이 끝까지 간다
- [ ] 취소 → 멈추고 "취소". **취소했으면 터미널 2 를 다시 켠다** (안 켜면 새 동작 전부 거부). 켜기 전에 피크·접촉 상태를 눈으로 본다
- [ ] 일시정지 → 재개를 **팔이 허공에서 이동하는 중에** 여러 번 걸어 본다 (줄·페그·거치대에 닿아 있을 때는 누르지 않는다)
  - 그 자리에서 멈추는지, 재개하면 남은 이동을 잇는지
  - 발현 스트로크(피크가 줄을 긁는 짧은 구간) 중에 누르면 스트로크가 끝난 뒤 멈추는 게 정상

### 나오면 바로 공유할 문구 (PM 요청)

이 넷 중 하나가 뜨면 그 이동은 실패하고 이후 이동이 전부 막힌다. 로봇 노드 재시작이 필요하다.

- `이동은 종료됐지만 목표 미도달 — 후속 이동 차단` → 5절 "허용오차 완화" 먼저
- `비동기 이동 시작/완료 확인 불가 — 후속 이동 차단`
- `일시정지/재개 제어 실패 — 현장 복구 확인·robot_controller 재시작 전까지 새 동작을 받지 않는다`
- `재개/이동 완료를 확인할 수 없는 로봇 상태` (보호정지·교시 모드 등)

같이 볼 것
- 이동이 눈에 띄게 느려졌는지 (이동마다 0.1초 간격으로 완료를 확인하므로 줄당 1~2초는 정상)
- 속도 상한(관절 60deg/s · 손끝 250mm/s)은 비동기 전환과 무관하게 그 전에 잘린다. 넘는 것처럼 보이면 공유

## 5. 막혔을 때

**"목표 미도달"** — 허용오차 0.5mm / 0.1도가 실측 전 임시값이다. 빌드 없이 넓혀서 로봇 노드를 다시 켠다
(`robot.launch.py` 가 이 인자를 안 받고, 시작할 때 한 번 읽어서 `ros2 param set` 도 안 먹는다):

```bash
ros2 run tunio_robot robot_controller --ros-args -p dry_run:=false \
  -p motion_position_tolerance_mm:=2.0 -p motion_angle_tolerance_deg:=0.5
```

**"서비스 미연결"** (일시정지·재개·정지) — 두산 브링업(터미널 1)이 살아 있는지, `ros2 service list | grep dsr_controller2`. 일시정지·재개가 "거절" 만 됐으면 작업은 계속 돈다.

**"goal 거부 (로봇: …)"** — 괄호 안이 로봇이 말한 이유. "재시작 필요" → 터미널 2 재시작 / "실행 중" → 잠시 대기 / "등록값 없음" → 재등록.

**일시정지·재개가 이상하다** — 시연에서는 일시정지를 빼고 취소만 쓴다.

**호박색 "로봇 알림: 피크 … 홈 복귀 완료"** — 피크를 거치대에 다시 꽂고 웹 **재개**. 같은 줄부터 다시 한다. 여기서 취소하면 로봇 노드 재시작.

**페그를 너무 많이/적게 돌린다** — `ros2 param set /task_manager adaptive_gain false` (재시작 없이 다음 조절부터 yaml 값 그대로).

**측정이 계속 '소리 부족'** — `device:=`, 마이크 위치, OS 마이크 향상 기능 끔.

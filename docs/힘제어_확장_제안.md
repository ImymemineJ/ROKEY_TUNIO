# 제안 — 로봇의 두 번째 감각을 쓴다

> 작성 2026-09-21 (정정인 · tunio_audio). 팀 논의용 초안.
> "아키텍처가 너무 단순해 보인다. 힘 제어·순응제어 등 두산 로봇 기능을 최대한
> 활용하는 방향으로 발전시킬 게 없나" 라는 질문에서 나왔다.

## 한 줄

**구조가 단순한 게 아니라, 로봇의 감각을 하나만 쓰고 있다.**

이 프로젝트의 전제가 **"비전 없이"** 다. 그러면 로봇에게 남은 감각은 **마이크와 힘**
둘뿐이다. 마이크 쪽은 끝까지 짜냈다 — onset 검출, FFT 돌출 문턱, 겹친 창 일치,
옥타브 차단, 발현 세기 편향 보정. **힘 쪽은 이제 막 시작했다.**

---

## 1. 지금 어디까지 왔나 (2026-09-21 기준)

### 쓰고 있는 것

```
movej · movejx · movel · get_current_pos*          위치 제어
get_tool_force                                     읽기
task_compliance_ctrl / release_compliance_ctrl     순응
set_desired_force / release_force                  힘 상한
check_force_condition                              접촉 감지
```

뒤의 셋은 **`register_peg()` 의 페그 진입 한 군데에만** 들어가 있다
(`motion_primitives.py` `_insert_force_controlled`). 순응을 켜고 상한 3.0N 으로
밀어 넣다가 2.0N 에 막히면 "손잡이가 서 있다" 로 판정하고 멈춘다.

그리고 **기본값이 꺼져 있다** — `peg_register_force: False` (#51). 통합 뒤로 미뤘다.

### 아직 안 쓰는 것

```
amovej / amovel        비동기 이동 (도는 중에 읽을 수 있다)
set_stiffnessx         강성 직접 지정
move_spiral            나선 탐색
```

### 비어 있는 자리

- **`pluck_string` 은 위치 제어만이다.** 주석에 그대로 적혀 있다 —
  *"줄 튕기기 1차 구현 (위치 제어만). 힘 제어·피크 집기는 2단계에서 붙인다"*
- **`adjust_peg` 에 과토크 정지가 없다.** 줄이 끊어지는 걸 막는 게 아무것도 없다
- **줄을 힘으로 찾는 동작이 없다.** 발현 좌표는 전부 교시값에 의존한다

## 2. 1순위 — 발현을 힘 제어로

**값어치가 제일 크고, `tunio_audio` 의 막힌 이슈를 직접 푼다.**

### 지금 무엇이 문제인가

지금은 *"여기로 가서 옆으로 8mm 밀어라"* 다. 그러면 피크가 줄을 얼마나 세게
치는지가 **좌표 정확도에 달려 있다.** 그런데 —

```
직접교시 옆 방향 오차     실측 1.1mm
기타 배치                 사람이 한다 (매번 다르다)
줄 높이                   줄마다 다르다
```

**1mm 어긋나면 헛치거나 너무 깊게 박힌다.** 그래서 돌출이 회차마다 흔들린다.

### 바꾸면

*"3N 으로 누르면서 훑어라"* 가 된다. 좌표가 좀 틀려도 같은 힘으로 친다.

### 왜 이게 #6 의 열쇠인가

이슈 #6(로봇 발현의 돌출 문턱과 타현 세기)이 막혀 있는 진짜 이유는
**"타현 세기" 를 지정할 방법이 없어서**다. 위치로는 세기를 못 정한다.

**힘으로 하면 숫자가 된다** — `pluck_force_n: 3.0`. 그러면 —

- **#6** (타현 세기 목표) — 실측으로 정하면 끝난다
- **#7** (5번 오검출 트레이드오프) — 발현이 일정해지니 문턱 결정이 깨끗해진다
- **6번 줄 y축 미세 조정** — 좌표 정밀도 요구가 확 낮아진다

### 설계에 이미 허락돼 있다

CLAUDE.md 3.1 —

> 힘 센서는 조율 판정이 아니라 아래에만 쓴다: **타현 세기 유지(2~5N)**, 접촉 탐색, 과토크 안전정지.

**설계에 있는데 구현이 안 된 것**이다. 새 결정이 필요한 게 아니다.

## 3. 2순위 — 터치오프로 줄을 스스로 찾기

**발표에서 제일 멋진 얘기가 될 것이다.**

```
피크를 줄 위에서 천천히 내린다
   ↓
힘이 0.5N 걸리는 순간 멈춘다        ← check_force_condition
   ↓
거기가 줄이다. 좌표를 기록한다
   ↓
그 자리에서 힘 제어로 훑는다        ← 1순위
```

**"로봇이 눈 없이 손끝 감각으로 줄을 찾는다."** 비전 없이 한다는 전제와 딱 맞고,
교시 오차·기타 배치 편차를 통째로 흡수한다. **시연 직전에 기타를 다시 놔도 안 깨진다.**

이슈 #20(피크 돌출 길이 터치오프)이 같은 기법이다. 팀이 이미 방향은 잡았다.
그리고 `register_peg` 가 페그 진입에서 **이미 같은 구조를 쓰고 있다** — 새로 만드는 게
아니라 대상만 페그에서 줄로 바꾸는 것이다.

---

## 4. 3순위 — 과토크 안전정지

**지금 줄이 끊어지는 걸 막는 게 아무것도 없다.**

CLAUDE.md 에 "목표 음에서 줄이 끊어지는 여유는 약 450센트" 라고 적혀 있고,
`tools/peg_cal.py` 에 200센트 소프트 리밋이 있긴 하다. **그런데 그건 측정 도구에만 있다.**
`robot_controller` 의 `adjust_peg` 에는 없다.

```
돌리는 중에 토크가 임계를 넘으면 즉시 정지
```

**시연 중에 줄이 끊어지면 그걸로 끝이다.** 작은 코드인데 보험이 크다.

---

## 5. 4순위 — 비동기 이동으로 "돌면서 보기"

이것이 3순위를 제대로 가능하게 하는 받침이다.

지금 `movej` 가 **끝날 때까지 안 돌아와서** 도는 중에 토크를 못 읽는다.
그래서 `tools/peg_turn_check.py` 가 **2.5도씩 끊어 돌고 멈춰서 읽는다.**

`amovej` 로 바꾸면 **돌면서 계속 읽는다.** 그러면 —

- 과토크를 실시간으로 잡는다
- 페그 파지 확인(토크)도 연속 데이터가 된다
- 끊어 도는 오버헤드가 없어져 **회전이 빨라진다** (`turn_vel 2.0 deg/s`, 사이클 타임)

## 6. 5순위 — 순응제어 밀림 방지

정묵이 #31 에서 이미 짚었고 `register_peg` 에 들어갔다. base Y 에 순응을 걸어
페그로 밀고 들어갈 때 **기타를 안 밀게** 한다.

순응을 **각도 정렬용으로 쓰는 것은 계산으로 안 된다고 증명됐다.** 이 용도로만 쓴다.

지금 기본값이 꺼져 있으므로(#51), **남은 일은 새로 만드는 게 아니라 켜는 조건을
정하는 것**이다.

---

## 7. 아키텍처가 실제로 두꺼워진다

이것들이 들어가면 구조가 이렇게 늘어난다.

- `TuningSettings` 에 **힘 파라미터** — `pluck_force_n`, `max_peg_torque_nm`
- **터치오프 단계**가 Phase 에 추가 — `PHASE_TOUCH_OFF`
- `teach_points.yaml` 에 **힘 임계값** 절
- `PlayString` Result 에 **실제 접촉 좌표** 회신 (다음 회차에 재사용)
- 새 실패 사유 — `FAIL_OVERTORQUE`, `FAIL_NO_CONTACT`

### ⚠️ 인터페이스 변경에는 비용이 있다

CLAUDE.md 7절 — 열거 상수는 **뒤에 추가만** 한다. 그리고 `MeasurePitch.FAIL_*` 에
상수를 추가하면 **반드시 `StringResult` 에도 같은 번호로** 넣어야 한다.
한쪽에만 넣으면 서버가 복사했을 때 **에러 없이 조용히 틀린다.**

시연 전에 건드리는 건 위험하다. **번호만 미리 예약해 두는 것**도 방법이다.

## 8. 일정 — 시연이 9/29~30 이다

**지금 넣을 만한 것 — 3순위(과토크 정지)와 6절(순응 켜는 조건).**
둘 다 작고 안전 쪽이라 위험이 낮다.

**1·2순위는 크기가 있다.** 다만 **1순위는 #6·#7 을 직접 푼다.** 최소한
"이 방향으로 간다" 는 합의는 지금 받아 두는 게 좋다. 안 그러면 #6 은 시연까지
"로봇 발현 세기를 못 정한다" 로 남는다.

**2·4순위는 시연 후**가 현실적이다. 다만 아키텍처 그림에 **"다음 단계"로 표시**해
두면 발표에서 *"여기까지 했고 이렇게 확장된다"* 가 된다.

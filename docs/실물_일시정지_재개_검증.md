# 실물 일시정지·재개 변경과 검증

2026-09-23. 작업 위치: `/tmp/tunio-web-registration-pr`.
통합 시험 브랜치: `feat/robot-pause-resume-test`. PR 생성·병합 전 실물 검증용이다.

## 버튼의 의미

- **일시정지**: 진행 중인 이동에 두산 `MovePause`를 요청하고 후속 이동·그리퍼 명령을 막는다.
- **재개**: 정상 로봇 상태를 확인하고 `MoveResume`으로 남은 이동을 잇는다. 같은 이동 명령을 다시 보내지 않는다.
- **취소**: 기존 Soft Stop 경로로 현재 이동을 끝내고 작업을 종료한다. 자동 복귀하지 않는다. 취소한 작업은 재개할 수 없다.
- 보호정지·비상정지·교시·복구·알 수 없는 상태에서는 재개하지 않는다. 제어 확인 실패는 정지/오류로 처리한다.
- 일시정지 요청을 처리하는 동안에도 웹 취소 버튼을 사용할 수 있다.

이 기능은 **소프트웨어 작업 제어**다. 하드웨어 비상정지 기능을 대체하지 않는다.
실제 정지 지연, 감속 거리, 파지·접촉 상태 유지와 재개 경로는 실물 검증 전이다.
이미 전달된 그리퍼 I/O는 되돌릴 수 없고 순응제어 중에는 외력에 의해 자세가 바뀔 수 있다.
힘을 가하는 `set_desired_force` 구간은 그대로 멈춘 자세를 보장할 수 없어 일시정지 요청을
거부하고 취소/정지 경로로 전환한다. 정상 pause/resume 대상은 위치 이동이다.

## 기존 이동 호출을 바꾼 이유와 제한

설치된 두산 드라이버는 동기 이동과 pause/resume 서비스를 같은 콜백 그룹에서 처리한다.
동기 이동이 끝날 때까지 pause 요청이 밀리므로 일반 이동은 `amovej/amovejx/amovel`로
접수하고, `CheckMotion=IDLE`, 정상 로봇 상태, 실제 목표 도달을 확인한 뒤 다음 단계로 간다.
각도는 누적 J6를 임의로 360도 환산하지 않으며 Cartesian 자세는 ZYZ 회전행렬로 비교한다.

두산 비동기 래퍼는 radius를 0으로 바꾸므로 **radius=3인 발현 스트로크는 기존 동기 호출을
유지한다. 그 짧은 스트로크 중 누르면 스트로크가 끝난 다음 멈춘다.** 모든 순간에 정확히
그 자리에 즉시 멈추는 기능으로 해석하면 안 된다. 속도·교시점·경유 좌표는 바꾸지 않았다.
비동기 전환과 상태 조회에 따른 실제 타이밍 변화는 현장에서 확인해야 한다.

## 관제·오디오 처리

- `/robot/pause`, `/robot/resume`: `tunio_interfaces/srv/CommandTuning`, 빈 요청.
- `/tuning/pause`, `/tuning/resume`가 위 서비스를 호출한다. 성공 응답을 받기 전에는 웹에
  일시정지 완료 상태를 발행하지 않는다. 성공 응답은 드라이버 명령 수락이며 별도 물리 정지 인증은 아니다.
- 일시정지 시간은 로봇 Action 결과 대기 예산에서 제외한다.
- 오디오 분석은 자체 타이머를 유지한다. 일시정지가 끼어든 회차의 측정값은 버리고,
  재개 후 기존 발현 Action 종료를 확인한 뒤 준비→새 측정→새 발현을 수행한다.
  이는 정상 발현 중복이 아니라 중단된 측정의 재시작이며 측정 실패 재시도 횟수를 소비하지 않는다.
- 측정 종료가 확인되지 않으면 새 측정을 겹쳐 시작하지 않는다.

## 로봇 없이 확인하기

이미 같은 도메인에서 실행한 시험 노드는 먼저 종료한다. 다른 실물 노드와 섞지 않는다.
아래는 가상 로봇·가상 오디오만 실행하며 실제 로봇 명령을 보내지 않는다.

```bash
cd /tmp/tunio-web-registration-pr
source /opt/ros/jazzy/setup.bash
colcon build --packages-select tunio_interfaces tunio_robot tunio_server tunio_bringup --symlink-install
source install/setup.bash
export ROS_DOMAIN_ID=194
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
unset ROS_DISCOVERY_SERVER ROS_SUPER_CLIENT
ros2 launch tunio_bringup sim_all.launch.py speed:=real port:=8091 db:=/tmp/tunio_pause_test.db
```

브라우저 `http://localhost:8091`에서 다음 순서로 확인한다.

1. 페그 재등록을 누르고 완료를 기다린다.
2. 시작 → 발현 또는 페그 조절 중 일시정지를 누른다.
3. 일시정지 표시 후 잠시 기다린다. 다음 줄로 진행하지 않아야 한다.
4. 재개를 누른다. 같은 작업이 이어져야 한다. 측정 중 멈췄다면 새 측정 번호로 다시 측정한다.
5. 다음 회차에서는 일시정지 후 취소한다. 재개 없이 취소로 종료돼야 한다.

## 실물 확인 전과 확인 순서

**관제 PC만 수정해서는 적용되지 않는다.** 로봇 PC도 이번 변경 파일을 받아 빌드하고
robot_controller를 재시작해야 한다. 로봇 PC에서 다음 순서로 받는다.
로컬 변경 때문에 switch가 거부되면 강제로 덮어쓰지 않는다.

```bash
cd /home/mook/tunio_ws
git status --short
git fetch origin
git switch feat/robot-pause-resume-test
git pull --ff-only origin feat/robot-pause-resume-test
source /opt/ros/jazzy/setup.bash
source install/setup.bash
colcon build --packages-select tunio_interfaces tunio_robot --symlink-install
source install/setup.bash
ros2 launch tunio_robot robot.launch.py dry_run:=false
```

두산 드라이버는 기존 실물 실행 명령을 유지한다. 위 터미널도 기존 드라이버 의존성과
양쪽 PC의 ROS_DOMAIN_ID·Discovery Server 설정이 맞아야 한다.
시뮬레이션의 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST 설정은 해제한다.
관제 PC는 이 작업 위치에서 재빌드·source 후 `station.launch.py`로 실행한다.

1. 로봇 담당자와 함께 접촉 없는 이동에서 일시정지 → 자세 유지 → 재개를 먼저 확인한다.
2. 재개 시 새 이동을 중복 실행하지 않고 원래 목표까지 이어지는지 확인한다.
3. 위치 이동 중 취소를 누르면 현재 이동이 끝나기 전에 감속·정지하는지 확인한다.
4. 취소 후 재개가 거부되고 후속 이동/자동 복귀가 없는지 확인한다.
5. 위 확인 뒤 피크를 든 이동·발현·페그 파지 상태의 정지와 재개를 각각 확인한다.
   스트로크의 제한은 위 설명과 같다. 힘 제어 구간은 정상 재개 시험 대상에서 제외한다.
6. 실물 취소 또는 제어 오류 후에는 접촉·피크 상태를 현장에서 복구하고 로봇 노드를 재시작한다.

## 조정 가능한 임시값

- robot_controller: `cancel_stop_timeout_sec=5.0`, `cancel_stop_interval_sec=0.1`을
  제어 서비스 응답 대기·상태 확인에도 사용한다.
- robot_controller: `motion_position_tolerance_mm=0.5`, `motion_angle_tolerance_deg=0.1`.
  비동기 이동 완료 판정용이며 실측 전이다. 감속 거리나 충돌 여유를 뜻하지 않는다.
- task_manager: `robot_control_timeout_sec=20.0`.
- web_node: `robot_control_timeout_sec=25.0`. pause/resume HTTP 응답 대기용이다.
  오래 기다리는 것은 이동을 더 하라는 의미가 아니다.

## 자동 검증 범위

로봇 API 대역: 비동기 이동 중 pause/resume, 같은 이동 재전송 방지, 목표 미도달 실패,
보호정지·미확인 상태 재개 거부, 취소 우선, 발현 스트로크 기존 호출 유지.
ROS 통합 대역: 관제 서비스→가상 로봇, Action 예산보다 긴 pause, resume 후 오디오 재측정,
pause 중 cancel. **실제 로봇의 새 pause/resume 및 새 Soft Stop은 아직 실기 검증 전이다.**

자동 검증 결과: `colcon test` 로봇 392개 + 관제 101개 = **493개 통과**.
웹 팝업·등록 상태·pause 응답 대기 중 cancel 및 늦은 응답 경합도 JavaScript VM으로 통과했다.
로그: `/tmp/pause-test3.log`, `/tmp/pause-server-final.log`, `/tmp/pause-final-build.log`.
이 수치는 소프트웨어 대역 검증 결과이며 실물 정지 성능의 검증 결과가 아니다.

웹 정적 파일의 symlink-install 경로 오류를 함께 수정했다. 관제 101개 검증 로그: `/tmp/web-static-isolated-test.log`.
